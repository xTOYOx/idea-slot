# アイデアスロット Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 日本語の単語・動詞・ゲームジャンル・タグを 2〜4 枠でランダムにかけ合わせる、スロット風の静的Webアプリを作り、GitHub Pages で公開する。

**Architecture:** 辞書データは Node スクリプトで日本語WordNet（SQLite）から事前に JSON に変換する。アプリは素の HTML/CSS/ES modules。ロジック（語の集合づくり・抽選・保存）は DOM に依存しないモジュールに分けて `node --test` で検証する。画面（`app.js`）はそれらを呼ぶだけにする。

**Tech Stack:** HTML / CSS / JavaScript（ES modules、依存なし）、Node 24（`node:sqlite`・`node:zlib`・`node --test`）、GitHub Pages

**Spec:** `docs/superpowers/specs/2026-10-16-idea-slot-design.md`

## Global Constraints

- 依存パッケージなし（`package.json` は `"type": "module"` と test スクリプトのためだけに置く）。ビルド工程なし
- 枠の数は 2〜4。演出は1秒弱。履歴は直近100件
- 単語は常に全語から出す（頻度フィルタなし）
- localStorage キー: `slot.settings` / `slot.history` / `slot.favorites` / `slot.custom` / `slot.excluded`
- 保存の読み書きは try/catch。壊れていたら初期値で起動
- 表示は日本語。ジャンル・タグは `{"ja","en"}` で持ち、`ja` を表示
- スマホ幅 375px で横スクロールが出ないこと
- 公開リポジトリ: `xTOYOx/idea-slot`（ブランチ `master`、ルートから Pages 配信）

## 種類キー（全タスク共通）

| キー | 中身 |
|---|---|
| `noun:animal` `noun:plant` `noun:food` `noun:person` `noun:place` `noun:tool` `noun:nature` `noun:body` `noun:feeling` `noun:event` `noun:abstract` `noun:other` | 単語の小分類 |
| `noun` | 単語の全小分類の和集合 |
| `verb` | 動詞 |
| `genre` | ゲームジャンル |
| `tag:look` `tag:mood` `tag:mechanic` | タグの小分類（見た目／雰囲気・テーマ／仕組み） |
| `tag` | タグの和集合 |
| `any` | 上の全部の和集合 |

表示名は `src/types.js` の `TYPE_LABELS`（Task 3）に置く。

## Review Focus

1. **全枠ホールドで「かけ合わせる」** → 何も変わらず、エラーも出ない（Task 3 のテスト）
2. **語の数が枠の数より少ない種類を複数枠に選ぶ**（除外を重ねた小分類など） → 埋められる枠だけ埋め、残りは `null`（「語がありません」）。無限ループしない（Task 3 のテスト）
3. **枠の種類を変えたとき、その枠がホールド中** → ホールドを外し、値を消す（古い種類の語が残らない）（Task 3 のテスト）
4. **関係ない JSON や壊れたファイルを読み込む** → エラーを出し、今のデータは変えない（Task 4 のテスト）
5. **localStorage が使えない環境**（プライベートモード等で例外） → メモリ上で動き続ける（Task 4 のテスト）

加えて、演出中に連打しても二重に回らないことを Task 5 のブラウザ確認で見る。

### Task 3: 語の集合づくりと抽選（純粋ロジック）

**Files:**
- Create: `src/types.js`, `src/pools.js`, `src/pick.js`, `tests/pools.test.mjs`, `tests/pick.test.mjs`

**Interfaces:**
- Consumes: Task 1・2 のデータ形
- Produces:
  - `src/types.js`: `TYPE_LABELS: Record<TypeKey, string>`（例 `'noun:animal': '動物'`、`any: '全部ランダム'`、`'tag:look': 'タグ：見た目'`）。`TYPE_KEYS: TypeKey[]`（表示順）
  - `src/pools.js`: `buildPools(data, custom, excluded) → Record<TypeKey, string[]>`
    - `data = {words, verbs, genres, tags}`（読み込んだ JSON そのまま）
    - `custom: Record<TypeKey, string[]>`（自分で追加した語。和集合キー `noun` `tag` `any` には入らない前提）
    - `excluded: string[]`
    - ジャンル・タグは `ja` の文字列にする。custom を対応する種類と和集合キーに足す。excluded の語はすべての集合から除く
  - `src/pick.js`:
    - `Slot = {type: TypeKey, value: string|null, held: boolean}`
    - `spin(slots: Slot[], pools, rng = Math.random) → Slot[]`：ホールドしていない枠に新しい値を入れた**新しい配列**を返す
    - `rerollOne(slots, i, pools, rng) → Slot[]`：i 番目だけ振り直す（ホールド中でも振り直す）
    - `setSlotType(slots, i, type) → Slot[]`：種類を変え、`value: null, held: false` にする
    - `resizeSlots(slots, n, defaultType = 'any') → Slot[]`：n（2〜4）個に詰めるか足す。残る枠は保つ

### Task 4: 保存（localStorage・書き出し・読み込み）

**Files:**
- Create: `src/store.js`, `tests/store.test.mjs`

**Interfaces:**
- Produces: `createStore(storage) → Store`（`storage` は `getItem/setItem` を持つもの。ブラウザでは `localStorage` を渡す。アクセス自体が例外を出す場合に備えて、呼ぶ側で `try { localStorage } catch { null }` として渡し、`null` ならメモリだけで動く）
  - `Store.state = {settings, history, favorites, custom, excluded}`
    - `settings = {count: 3, slots: [{type: 'any'} ×3], animate: true}`（初期値）
    - `history: string[][]`（新しい順、最大100）
    - `favorites: Array<{combo: string[], memo: string, savedAt: number}>`
    - `custom: Record<TypeKey, string[]>`、`excluded: string[]`
  - `Store.save(key)`：`slot.<key>` に JSON で書く。例外は握りつぶす
  - `Store.pushHistory(combo: string[])`：先頭に足し、100件に切る。保存も行う
  - `Store.exportJSON() → string`：`{app: 'idea-slot', version: 1, ...state}`
  - `Store.importJSON(text) → {ok: true} | {ok: false, error: string}`：`app !== 'idea-slot'` や形の崩れは `ok: false`。そのときは state を変えない
