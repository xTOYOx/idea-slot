## 動画（自動で作る）

```
node tools/video.mjs --promo   # 正方形の宣伝動画（字幕・効果音つき）
node tools/video.mjs           # 16:9 の画面録画だけ（字幕なし・効果音つき）
```

- `--promo`: `out/idea-slot-promo.mp4` ができる（1080×1080、30fps、H.264 + AAC、約31秒、約25MB。X にそのまま上げられる）。上に字幕、真ん中に本物の `?demo`、下にアプリ名と URL。前半（約16.6秒）は、回す→LOCK→回し直し→IDEA!→テーマ選び。後半（約11秒）は、リールの本数とテーマを変えた4つの場面（4・7・5・3本）で、場面の間は 0.45 秒のクロスフェード（替わる直前の絵を重ねて透かす）。「あなたに、新しい発想を。」の字幕を出し続け、27.9 秒から画面全体を暗くぼかして、サイトのカード画像（`og.png`）をそっと重ねて 31.0 秒まで見せる
- なし: `out/idea-slot-demo.mp4`（1920×1080、約29.3秒、字幕なし・場面の切り替えに白い光なし）
- どちらも `?demo` の台本（約28.5秒）を、時計を止めて1コマずつ撮るので、PC が重くてもカクつかない。`--promo` で3〜4分かかる
- 効果音は、アプリの音（`src/sound.js`）を鳴らした時刻の記録から、同じ音を作り直して付ける（ブラウザの音を録音はしない）。最大 -6dB に揃える
- 撮り終わると `out/promo-check/`（または `out/demo-check/`）に確認用のコマと、一覧 `out/promo-contact.png` を書き出す。`--encode-only` で撮り済みのコマから mp4 だけ作り直せる（`--sec=N` で頭から N 秒だけ試作）
- 字幕を直すときは `tools/promo.html` の `CAPS`、流れを直すときは `src/demo.js` の `DEMO_SCRIPT`
- `out/` は git に入らない。残したい動画は別の場所にコピーしておく
- mp4 にまとめるとき、jsDelivr から mp4-muxer（5.1.5）を読むので、ネットにつながっている必要がある
- コインの飛び方などは毎回少し変わる。気に入らなければ撮り直す

## 録画の手順（手で撮る場合・28秒前後の動画）

デモ用の URL を開くと、決まった流れを自動で1回演じます。保存データには何も書きません。

- 1回だけ演じる: https://toyogame.github.io/idea-slot/?demo
- 繰り返し演じる（撮り直しやすい）: https://toyogame.github.io/idea-slot/?demo&loop

流れ（全部で約28.5秒）:
1. 2.2秒待つ（止まった筐体）
2. レバーで回し、3本が順に止まる（ドラゴン・眠る・落ちものパズル）
3. 指が1番の LOCK を押して固定
4. もう一度回し、ほかの2本だけ回り直す（ドラゴン × 料理 × ローグライク）
5. 指が IDEA! を押して当たり。コインが噴き出して受け皿に積もる
6. 指が2番のモニターを押してテーマえらびを開き、「妖怪・神話」にチェックして閉じる
7. 16.6秒から、リールの本数と種類が一瞬で替わる4つの場面が続く。どれもすぐ回り、左から順に止まる
   - 4本（座敷わらし・配達する・カードバトル・銭湯）
   - 7本（猫・宇宙ステーション・修理する・ローグライク・深夜のコンビニ・夏祭り・ワンボタン操作）
   - 5本（魔法使い・カレー・育てる・タワーディフェンス・雪の日）。止まって0.5秒後に指が IDEA!
   - 3本（ゴースト・引っ越し・リズムゲーム）。同じく IDEA!

撮り方（Windows）:
1. ブラウザを横長の窓にする。目安は 1280×720 か 1920×1080
2. 筐体が画面いっぱいになるくらいに置く
3. `?demo&loop` を開き、Win + Shift + S → 「録画」で、筐体のまわりを範囲選択して録る
4. 2周目の頭から1周ぶん（約28.5秒）を残すと、きれいに始まって終わる

スマホ向けに縦長も撮るなら、ブラウザの開発者ツールで 390×844 にして同じように撮ります。
X の動画は、横長 16:9 か正方形が、タイムラインで大きく見えます。

### 考え方
- 一般の集計では、日本の X は夜 21〜23時に反応が集まりやすい（[timetopost.co](https://timetopost.co/best-time-to-post/twitter/japan/)）。ただし自分のアカウントでは違ったので、下の分析を優先する
- 反応は投稿から最初の1時間、特に最初の15分の返信で伸び方が決まる。**投稿してから1時間は返信できる時間を選ぶ**
